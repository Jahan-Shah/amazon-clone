# Amazon Clone - Project Overview

<!-- blueprint:source-hash 03b547c740f5dbd109f84824309973c723b0c667c650030609fe0b19987211d8 -->

> A fast, clean rebuild of the core Amazon shopping flow - browse, product,
> cart, checkout, order history - delivered inside a 24-hour window.

## Problem

Recreate the essential Amazon.com shopping experience as a working, deployed
e-commerce app. It is judged on speed of delivery, product judgment (what was
prioritized vs. cut), and UX/UI quality - not feature parity with the real
Amazon.

## Users

- **Guest visitor** - browses and searches fully without an account.
- **Registered shopper** - signs up with email/password, carts, checks out.
- **Returning shopper** - logs back in and views past orders.

No seller, admin, or marketplace role exists in v1. Auth is required only for
checkout and account pages; browsing and search are open.

## Usage model

- 24-hour timed build window; portfolio/assignment product, not monetized.
- No real payments: Stripe runs in test mode only.
- Explicit non-requirements (deliberate v1 cuts, each a v2 candidate): seller
  accounts, product Q&A, recommendations, coupons/gift cards/subscriptions,
  returns/refunds, multiple payment methods, admin/inventory dashboard.

## Features

Build order from `build-plan.md`; first three are the data/auth foundation
slices, the rest are user-facing.

1. **Data model + seed script** - Product and Review catalog models, ~80 seeded
   products across 5 categories, 2-4 reviews each.
2. **Better Auth setup** - Prisma adapter, email/password, generated auth schema.
3. **Address + Order + OrderItem models** - order persistence related to
   Better Auth's `User.id`.
4. **Homepage + browse/search + filters** - category sections, featured grid,
   keyword search, category filter, price/rating sort. Largest single item.
5. **Product detail page** - image gallery, price, stock, add-to-cart, star
   rating, seeded read-only reviews.
6. **Cart** - Zustand + persist (localStorage); add/remove/quantity, subtotal,
   survives reload for guests.
7. **Signup/login + protected routes** - auth pages and header account dropdown.
8. **Checkout** - single-page address + Stripe test payment + webhook, order
   confirmation. Headline differentiator: deliberately better than Amazon's
   fragmented multi-step checkout.
9. **Order history** - past-order list and order detail view.
10. **Polish pass** - loading/empty states, mobile responsiveness, one
    "better than original" bet.

## Data model

Money is integer cents everywhere (`priceCents`, `totalCents`); format for
display only. Postgres via Prisma.

### Product

- `id`, `title`, `slug` (unique, used in URL), `description`
- `priceCents` (int), `images` (string list), `category` (one of Electronics,
  Home, Books, Fashion, Toys), `rating` (float), `reviewCount` (int), `stock` (int)
- has many Review

### Review

- `id`, `productId` -> Product, `authorName`, `rating` (1-5), `body`
- Seeded only; not user-submitted in v1

### User, Session, Account, Verification

- Owned and generated by Better Auth's Prisma adapter; not hand-written

### Address

- `id`, `userId` -> User, `line1`, `line2` (optional), `city`, `state`, `zip`

### Order

- `id`, `userId` -> User, `addressId` -> Address
- `status` (pending | paid | shipped), `totalCents` (int), `createdAt`
- has many OrderItem

### OrderItem

- `id`, `orderId` -> Order, `productId` -> Product
- `quantity`, `priceCents` - price snapshot at purchase time

> Locked shapes: `OrderItem.priceCents` is a snapshot (order totals must not
> drift when product prices change), and all money stays integer cents. Later
> checkout and order-history features depend on both.

## Tech stack

- **Next.js 16.3.5** (App Router, installed) - plan says "Next.js 14"; see Open
  questions
- **TypeScript strict** - all app code
- **Tailwind CSS v4** - styling, CSS-first config in `app/globals.css`
- **Prisma + Postgres (Neon)** - data layer
- **Better Auth** - email/password auth, Prisma adapter, session-based
- **Zustand + persist** - cart state in browser localStorage
- **Stripe (test mode)** - PaymentIntents + webhook for payment confirmation
- **Vercel** - hosting

## Monetization

Not applicable - portfolio/assignment build. Stripe runs in test mode only; no
real charges.

## UI/UX

Guest-first: everything is browsable signed-out; only checkout and account
pages require login. Single-page checkout (address + payment together).
Mobile-responsive throughout. Empty states (empty cart, no orders, no search
results) are designed, not blank.

- `/` - homepage: category sections, featured product grid
- `/search` (or query on `/`) - keyword + category filter + sort
- `/product/[slug]` - detail: gallery, price, stock, reviews, add-to-cart
- `/cart` - quantities, subtotal
- `/checkout` - single page: address form + Stripe payment + confirmation
- `/orders`, `/orders/[id]` - order history and detail (auth required)
- `/login`, `/signup` - auth pages

## Deployment

- **Host:** Vercel. Next.js app; build `pnpm build`, start `pnpm start`.
- **Database:** Neon Postgres (connection string env var).
- **Env vars expected:** `DATABASE_URL`, `BETTER_AUTH_SECRET`,
  `BETTER_AUTH_URL`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`,
  `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`.
- **Stripe webhook:** needs an endpoint (e.g. `/api/webhooks/stripe`) receiving
  PaymentIntent events to mark orders paid.
